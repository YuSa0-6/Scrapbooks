# 測り方

`pnpm build` のあと `pnpm preview --host 127.0.0.1 --port 4322` で本番ビルドを動かし、`pnpm perf`（`scripts/perf.mjs`）が `http://127.0.0.1:4322`（`BASE_URL` で変えられる）に Playwright でつないで測り、表にして出す。予算を超えたら終了コード 1。`--json` で JSON、`--strict` で「未対応」も失敗にする。

- preview は開発サーバーと同じ `.wrangler/state` を使うので、先に 4321 で `dev-bypass` をしておくと見本データが見える
- `pnpm build` のあと、起動中の開発サーバーはエラーページになる。開発サーバーを再起動する
- 長いタスクは 3 回測って一番大きい値を見る（1 回ごとに 2 割ほどぶれる）

# フォント

Google Fonts の日本語フォントは、文字の範囲ごとに約 120 枚の `@font-face` に分かれて届く。3 つのフォントをそのまま使うと、HTML に 480 枚の定義（約 370KB）と 100 本超の `<link rel="preload">` が入り、最初のレイアウトが重くなる（CPU 4 倍で約 1.7 秒）。

`config/slim-fonts.mjs` の `slimGoogle()` が、Google のプロバイダーを包んで面を絞る。

| 残す面 | 理由 |
| --- | --- |
| 半角（latin）・かな・記号 | いつも使う |
| 漢字の面のうち、よく使う順に 30 枚 | Google の面は「あとのものほどよく使う」順に並んでいる。「日」「本」「見」などは最後の 1 枚に入る |
| 捨てる面 | 残りの漢字は端末の日本語フォントで表示する（見本の文章では、足りない漢字は「廊」「肖」「拾」など数字だけ） |

- 効果：HTML は 456KB → 143KB、`@font-face` は 482 枚 → 約 110 枚、preload は 119 本 → 3 本、長いタスクは約 4 割減った
- 見出しのフォントは、半角とかなの面だけ preload する（`Base.astro`）
- 新しい漢字を書いて、字が別のフォントで出るときは、`slimGoogle({ kanjiSlices })` の数を増やす

# 長いタスクの床

目標は 300ms だが、この測り方（ヘッドレス Chromium・CPU 4 倍）では届かない。日本語の文字を出すだけで床が高いため。

| 状態（表紙） | 長いタスクの合計 |
| --- | --- |
| すべての `@font-face` を外した | 566ms |
| さらに、日本語の文字を半角の `a` に置き換えた | 314ms |
| 今の実装（面を絞った日本語フォント） | 1200〜1450ms |
| 面を絞る前 | 約 2200ms |

- JS は原因ではない（JS を全部止めても 1157ms）
- 残りは日本語の文字の整形（shaping）と、フォントが届くたびの再レイアウト。`font-display: optional` にしても変わらなかった
- そこで予算を 1800ms（3 回の最大値の 1.25 倍ほど）にして、悪くなったことを見つける役にした。下げるには、日本語フォントの数を減らす（例：手書きフォントを外す）ほかない
